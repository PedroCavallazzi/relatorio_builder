modern report builder

A drag-and-drop report designer and REST rendering API that Oracle APEX calls directly to produce PDF or HTML reports — no Java, no iReport.

How it works

Architecture

Relatoolrio is a single Node.js process with two packages in an npm workspaces monorepo. The builder is a React SPA served as static files from the same process. The API handles template storage, data querying, and report rendering.

🖌️

packages/builder

React + GrapesJS drag-and-drop designer. Runs only in the browser. Talks to the API at /api/*.

⚡

packages/api

Express server. Serves the built SPA, stores templates in Oracle, renders via Handlebars and Puppeteer.

🗄️

Oracle DB

Two tables: report_templates for template storage and report_renders for audit logging.

📄

Puppeteer

Headless Chromium shared browser instance. One page per render request, closed after each render.

Database Setup

Run the migration script once as a DBA or a user with CREATE TABLE privileges:

-- packages/api/migrations/001_create_tables.sql

CREATE TABLE report_templates (
  id          NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name        VARCHAR2(200)  NOT NULL,
  description VARCHAR2(1000),
  grapes_json CLOB           NOT NULL,
  html_cache  CLOB,
  data_query  CLOB,
  created_at  TIMESTAMP DEFAULT SYSTIMESTAMP,
  updated_at  TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE TABLE report_renders (
  id          NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  template_id NUMBER REFERENCES report_templates(id),
  format      VARCHAR2(10),
  rendered_at TIMESTAMP DEFAULT SYSTIMESTAMP,
  caller      VARCHAR2(200)
);
⚠️

CLOB columns: grapes_json, html_cache, and data_query are stored as CLOBs. The API uses oracledb.fetchAsString = [oracledb.CLOB] to read them as plain strings automatically.

Variables & Data Binding

Templates use Handlebars.js syntax. At render time, the data sent in the API request body is injected into the template.

SyntaxProducesExample
{{variable}}Single value interpolation{{customer_name}} → ACME Corp
{{#each rows}}…{{/each}}Repeat for each object in rows arrayOne table row per query result row
{{image_url}}URL string for <img src>Logo passed as base64 data URL

The data object shape APEX should send:

{
  "format": "pdf",
  "data": {
    // top-level scalars → {{variable_name}} in template
    "customer_name": "ACME Corp",
    "invoice_no":    "INV-2026-001",

    // rows array → {{#each rows}} in DataTable
    "rows": [
      { "item": "Widget A", "qty": 10, "price": "100.00" },
      { "item": "Widget B", "qty": 2,  "price": "250.00" }
    ]
  }
}

Preview & Save

1

Enter a default SQL query in the Toolbar

This query runs only in the builder preview. APEX bypasses it and sends its own data at render time. Example: SELECT * FROM customers WHERE rownum < 5

2

Click Preview

The builder posts your SQL to POST /api/data/query, fetches a sample data set, then renders the current template as HTML in a popup iframe so you can see real data.

3

Click Save

Serialises the GrapesJS canvas to JSON (stored in grapes_json) and also generates an html_cache string. Both are persisted to report_templates in Oracle.

⚠️

Save before calling APEX: The render endpoint reads html_cache. A template that has never been saved — or was created but never designed — will return a 400 error. Always save after making changes.

Integration

Oracle APEX Integration

APEX calls the render endpoint via apex_web_service.make_rest_request. The template id appears in the URL; the format and data go in the request body as JSON.

Render a PDF and download it

DECLARE
  l_url      VARCHAR2(200) := 'http://report-server:3000/api/render/42';
  l_body     CLOB;
  l_response BLOB;
BEGIN
  -- Build JSON with your query results
  l_body := '{'
    || '"format":"pdf",'
    || '"data":{'
    ||   '"customer_name":"' || :P1_CUSTOMER || '",'
    ||   '"invoice_no":"'    || :P1_INVOICE_NO || '",'
    ||   '"rows":[]'   -- or build from a cursor loop
    || '}}';

  apex_web_service.set_request_headers(
    p_name_01  => 'Content-Type',
    p_value_01 => 'application/json'
  );

  l_response := apex_web_service.make_rest_request_b(
    p_url         => l_url,
    p_http_method => 'POST',
    p_body        => l_body
  );

  -- Trigger browser download
  sys.htp.init;
  owa_util.mime_header('application/pdf', FALSE);
  htp.p('Content-Disposition: attachment; filename="invoice.pdf"');
  owa_util.http_header_close;
  wpg_docload.download_file(l_response);
  apex_application.stop_apex_engine;
END;

Render HTML inline

DECLARE
  l_response CLOB;
BEGIN
  apex_web_service.set_request_headers(
    p_name_01  => 'Content-Type',
    p_value_01 => 'application/json'
  );

  l_response := apex_web_service.make_rest_request(
    p_url         => 'http://report-server:3000/api/render/42',
    p_http_method => 'POST',
    p_body        => '{"format":"html","data":{"name":"World","rows":[]}}'
  );

  -- l_response now contains the rendered HTML string
  htp.p(l_response);
END;
💡

Replace make_rest_request with make_rest_request_b when the response is a PDF (binary). For HTML responses, make_rest_request (CLOB) is fine.

Reference

API Reference

All endpoints are served at the same host as the builder UI. Base URL: http://<server>:3000.

Templates

MethodPathDescription
GET /api/templates List all templates. Returns id, name, description, updated_at.
GET /api/templates/:id Full template including grapes_json and data_query.
POST /api/templates Create. Body: { name, description, grapes_json, html_cache, data_query }.
PUT /api/templates/:id Update. Same body as POST.
DELETE /api/templates/:id Delete template and all its audit rows.

Data (builder preview)

MethodPathDescription
POST /api/data/query Run a SQL query and return rows as JSON. Body: { sql }. Used by the builder Preview button only.

Render (called by Oracle APEX)

MethodPathDescription
POST /api/render/:id Render template :id with the provided data.
Body: { format: "pdf"|"html", data: { ...vars, rows: [...] } }
Response: PDF binary or HTML string.

Health

MethodPathDescription
GET /api/health Returns { status: "ok" }. Use for load-balancer health checks.

Data Model

report_templates

ColumnTypeDescription
idNUMBERAuto-generated primary key.
nameVARCHAR2(200)Display name shown in the template list.
descriptionVARCHAR2(1000)Optional free-text description.
grapes_jsonCLOBFull GrapesJS project JSON. The source of truth for the designer canvas.
html_cacheCLOBPre-compiled HTML+CSS string. Read by the render endpoint — must be non-empty before calling APEX.
data_queryCLOBDefault SQL for the builder preview. APEX ignores this and sends its own data.
created_atTIMESTAMPSet on INSERT.
updated_atTIMESTAMPSet on INSERT and UPDATE.

report_renders

ColumnTypeDescription
idNUMBERAuto-generated primary key.
template_idNUMBERFK → report_templates.id.
formatVARCHAR2(10)pdf or html.
rendered_atTIMESTAMPWhen the render completed.
callerVARCHAR2(200)IP address of the caller (for audit).
📌

Out of scope (can be added later): user authentication, Excel/XLSX output, chart blocks, report scheduling, and email delivery. The current API has no authentication — it is intended for internal-network use only.
